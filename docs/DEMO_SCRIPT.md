# PriceRadar 项目演示稿

> 建议时长：8～10 分钟
> 演示目标：说明系统如何把每日 3C 报价转化为可复核、可查询、可监控、可预测的行情数据，并突出智能体不是单纯聊天，而是能够调用业务工具完成任务。

## 一、演示前准备

1. 启动 MySQL 和 Ollama，确认本地已有 `qwen2.5:7b`。
2. 双击项目根目录的 `start.bat`，打开 `http://127.0.0.1:5173`。
3. 准备一份新的报价 Excel；没有新文件时，可以使用已有批次演示复核。
4. 确认“行情问答”中已有至少一个已发布报价日期，价格预测最好有两个以上历史日期。
5. 为避免现场网络波动，联网搜索只作为加分演示；本地行情查询和预测不依赖公网。

## 二、开场介绍（约 40 秒）

大家好，我演示的项目叫 PriceRadar，是一个面向 3C 数码回收行业的行情信息助手。

传统工作方式主要依赖每天接收 Excel 或报价图片，再由人工整理型号、容量、颜色和价格。这个过程数据量大、容易重复，也很难快速判断某个价格是否异常。

PriceRadar 把整个流程连接起来：从数据导入、结构化清洗、人工与智能复核，到行情发布、涨跌监控、自然语言问答和短期价格预测。系统使用 Python、FastAPI、Vue、MySQL 和本地 Ollama 模型实现，不需要付费大模型 API。

## 三、数据来源导入智能体（约 1 分 30 秒）

### 操作

1. 点击左侧“数据来源导入智能体”。
2. 上传一份报价 Excel。
3. 展示后台处理进度。
4. 展示入库前检查：可直接复核、重点检查、重复报价和异常波动。
5. 选择需要的记录进入复核工作台。

### 讲解词

系统优先使用 Excel，因为它可以直接读取单元格，比图片 OCR 更稳定；只有没有表格时才使用图片识别。

文件上传后不是立刻写入正式行情，而是先解析成候选记录。系统会拆分品牌、型号、容量、颜色和价格，也能处理一行多个颜色价格，以及 `13**` 这类通配价格。

这里的后台进度是真实的逐文件处理进度。预检会提前标记重复、字段缺失和异常价格，减少后续人工复核的工作量。

## 四、复核诊断智能体（约 1 分 30 秒）

### 操作

1. 打开“复核工作台”。
2. 筛选“低置信度”或“需拆分”。
3. 点击一条记录，展示来源单元格或图片定位。
4. 演示整行编辑，增加或删除一个颜色价格。
5. 点击“一键智能审核”，展示自动通过和保留人工复核的结果。
6. 从自动通过记录中抽查一条，并展示审核日志。

### 讲解词

复核诊断智能体不会让大模型直接修改数据库。它先读取识别置信度、字段完整性、重复关系、历史价格和来源证据，再给出风险等级与修改建议。

对于证据充分、字段完整、风险较低的数据，系统可以自动通过；不确定的数据仍然留给人工。自动通过的数据支持抽查和撤销，所有操作都会写入审核日志，因此整个审核过程可追踪、可回退。

## 五、行情发布、概览与监控（约 1 分 20 秒）

### 操作

1. 发布已完成复核的批次。
2. 打开“市场概览”，按品牌查看涨跌情况。
3. 打开“行情监控智能体”，展示最新运行结果和高风险异常。
4. 打开一条异常，展示当前价格、上一期价格、来源和处置建议。

### 讲解词

发布后，候选报价才会进入正式历史。涨跌额按照相同型号、容量、颜色和辅助规格，与此前最近一期明确报价进行比较，通配价格和暂无报价不会参与精确涨跌计算。

行情监控会在发布后自动运行，识别大幅波动、报价数量骤减、容量倒挂、颜色价差以及型号新增或消失。智能体可以回查原始证据并提出建议，但最终修改仍需人工确认。

## 六、行情问答智能体（约 1 分 20 秒）

### 操作与示例问题

依次输入：

1. `红米 K80 12+256 最新报价是多少？`
2. `它和上一期相比涨了还是跌了？`
3. `最近涨幅最大的 10 个型号是什么？`
4. `结合公开市场信息，分析这个型号最近波动的可能原因。`

### 讲解词

行情问答不是让模型凭记忆回答价格。模型会先理解问题，再选择数据库行情、历史价格、价格预测或公开网页搜索工具，并根据工具返回的证据组织答案。

每个对话都有独立记忆，因此第二个问题中的“它”能够继承上一轮的型号、容量和颜色。内部报价与外部信息会明确区分，避免把网络信息误认为本系统的正式报价。

## 七、多周期价格预测（约 1 分 20 秒）

### 操作

1. 打开“价格预测”。
2. 输入一个具有多个历史日期的型号、容量和颜色。
3. 展示未来 1、3、7、10 天的中位价、区间、方向概率和置信度。
4. 重点打开 3 天预测及外部信号来源。

### 讲解词

预测对象优先精确到型号、容量和颜色。内部预测使用历史报价的稳健趋势与波动率计算，并限制异常单日价格对结果的影响。

联网信息只作为受限的方向修正，不能覆盖内部历史事实。预测最长不超过 10 天，默认重点展示未来 3 天；样本不足时系统会直接拒绝给出虚假的精确结果。等目标日期产生真实报价后，系统还会回测方向准确率、区间命中率和平均误差。

## 八、金山文档自动同步（约 50 秒）

### 操作

1. 展示根目录的 `sync-kdocs-now.bat`。
2. 双击运行，或展示最近一次同步日志。
3. 回到复核工作台，展示自动创建的新批次。

### 讲解词

每天更新的金山报价表由 Windows 任务计划程序自动下载，不需要 Codex 常驻。系统会计算文件的 SHA-256；内容没有变化时不会重复保存或创建批次，有变化时会保留带时间戳的历史文件，并自动完成预检后停在复核工作台。

自动同步不会越过审核直接发布，保证无人值守采集和人工质量控制之间的边界。

## 九、结束总结（约 40 秒）

PriceRadar 第一版已经跑通了从数据进入到行情应用的完整闭环。规则程序负责可验证的解析、计算和安全校验；本地大模型负责理解用户意图、调用工具、结合上下文和生成建议。

项目的核心价值不是单个 OCR 或聊天页面，而是把分散的日报价变成可追溯的结构化行情，并进一步支持监控、问答和预测。后续可以继续加入更多报价来源、预测模型评估、通知渠道和基于审核反馈的持续优化。

## 十、现场异常预案

- Ollama 未启动：先演示导入、复核、涨跌和确定性监控，并说明只有自然语言生成部分受影响。
- 公网搜索失败：使用内部行情问答和历史预测，说明外部信息只是辅助信号。
- 金山登录失效：双击 `setup-kdocs-auto-sync.bat`，在 Edge 中重新登录一次。
- Excel 被判定重复：说明 SHA-256 去重生效，改用一个新文件或直接展示已有批次。
- 预测提示样本不足：换用具有两个以上报价日期的型号，这也可以用于说明系统不会编造预测。
